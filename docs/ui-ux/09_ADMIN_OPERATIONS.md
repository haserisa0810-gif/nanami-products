# 管理・運用 UI/UX仕様書

## 1. 対象

- 管理YAML発行、結果確認
- Personal Editionコード発行とPDF生成
- APIキー発行
- 注文照会、リセット、メール同期
- DB初期化・期限切れデータ処理等の内部操作

購入者向けUIと異なり、管理画面は「操作しやすさ」より誤操作防止、監査可能性、秘密情報保護を優先する。

## 2. 認証と公開範囲

- 管理画面と内部APIはサーバー側認証を必須とする。
- 認証情報が未設定の場合は許可するのではなく拒否する。
- 秘匿URLだけを認証の代替にしない。
- 認証失敗と対象データ不存在を必要以上に区別して外部へ情報を与えない。
- 管理画面、コード、注文情報、顧客情報のレスポンスは `no-store` とする。

## 3. 管理発行

- 商品種別、言語、出生情報、時刻精度、期限を発行前に確認できる。
- 生成結果で購入者URL、YAML、プロンプト、期限を確認できる。
- 手動発行と購入者注文発行をDB上で区別する。
- テスト用の注文番号・アクセスコードを正式仕様書や公開ログへ記載しない。
- ACGを選択した場合は正確な出生時刻要件を管理画面でも検証する。

## 4. Personal Editionコード

- 発行する商品種別、言語、件数を明示する。
- コードは必要な場面だけ表示し、一覧やログへ秘密値を過剰露出しない。
- PDF一括生成は対象コード数と出力言語を確認してから行う。
- 使用済みコードを新規コードとして再表示しない。
- 生成失敗時に未使用コードを使用済みへ確定しない。

## 5. 注文照会・リセット

- 販売元と注文番号を組として照会する。注文番号だけで別販売元を混同しない。
- 注文明細、数量、使用済み枠、残枠、生成済み結果を区別して表示する。
- リセット対象は販売元、注文、SKU、明細、枠または結果を明示する。
- 一括リセットやDB削除を通常画面の主CTAにしない。
- 破壊的操作は確認文字列、理由、操作対象の再表示を必要とする。
- リセット後も監査に必要な履歴を失わせない。

## 6. メール同期

- メール同期は注文発行権のDB登録に関わるため、対象販売元と検索範囲を限定する。
- 認証済み内部APIからのみ実行する。
- 同じメールを再処理しても重複枠を増やさない冪等性を持つ。
- SKU、明細番号、数量を抽出し、数量分の発行権を作る。
- 未知SKU、解析不能、部分取得を成功として黙って登録しない。
- 同期結果は件数と警告を表示し、メール本文や顧客情報を不要に画面・ログへ出さない。
- Gmail等との接続切れは、注文不一致と区別できる運用アラートにする。

## 7. DB初期化と保守

- DB初期化APIは通常運用で手動データを消す機能ではなく、必要なschema／tableを `IF NOT EXISTS` で準備・検査する保守機能として扱う。
- 認証情報未設定時は拒否する。
- 本番DBのDDL、マイグレーション、削除、データ修正はデプロイ承認と別の明示承認を必要とする。
- 実行前に対象DB、project、schema、予定DDL、バックアップ／ロールバック方法を表示・記録する。
- アプリ起動時の安全な初期化と、手動内部APIの権限を混同しない。

## 8. エラーと監査

- 操作失敗時は、何が未実行か、再試行可能かを管理者へ示す。
- SQL本文、接続文字列、APIキー、アクセストークン、メール本文を画面へ出さない。
- 重要操作は日時、操作種別、対象の非秘密識別子、成否を記録する。
- 顧客情報や注文番号を仕様書、テストスナップショット、第三者レビュー資料へ含めない。

## 9. 受入テスト

### 自動テスト

- 管理・内部ルートが未認証で拒否される。
- 認証情報未設定時にDB初期化、同期、リセットが拒否される。
- メール同期が冪等で、SKU・明細・数量分の発行権を作る。
- 未知SKUと解析不能メールを安全に隔離する。
- 販売元別照会とリセットが別販売元の同一注文番号へ影響しない。
- Personal Editionコードの生成、使用、失敗時解放を検証する。
- 管理画面と内部レスポンスのキャッシュ禁止を確認する。

主なテスト: `tests/test_admin_yaml_basic_auth.py`, `tests/test_internal_init_db_auth.py`, `tests/test_admin_redemption_marketplaces.py`, `tests/test_gmail_mail_api.py`, `tests/test_stores_mail_sync_upsert.py`, `tests/test_marketplace_order_migration.py`, `tests/test_personal_edition_activation.py`。

### 手動テスト

- 本番相当の候補環境で、読み取り照会だけを先に行う。
- リセット、マイグレーション、DB変更は対象とロールバックを提示して別承認を得る。
- 実通知メールはテスト宛先とテスト注文だけを使い、送信先、件名、言語、秘密情報非表示を確認する。
- 本番後は同期失敗率、未照合注文、発行権枯渇、重複生成、5xxを監視する。
