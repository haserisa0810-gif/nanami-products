# 購入開始・注文引換 UI/UX仕様書

## 1. 対象

- `GET /start`, `GET /start/{product_slug}`
- `GET/POST /redeem`, `GET/POST /redeem/{product_slug}`
- `GET/POST /personal-edition/activate`
- Etsy / STORES / Payhip等で購入済みの利用者が、注文情報と出生情報を入力して鑑定を発行する体験

注文発行権と複数購入のデータ仕様は `docs/MULTI_PURCHASE_ORDER_ENTITLEMENTS_SPEC.md` を正本とする。

## 2. 利用者の目的

1. 自分が購入した商品内容と注意事項を確認する。
2. 購入情報と必要な出生情報を迷わず入力する。
3. 入力内容を最終確認し、対応する商品を1枠だけ発行する。
4. 発行済みの場合は、同じ注文の残枠または既存結果へ安全に進む。

## 3. 画面契約

### 3.1 購入開始

- 商品名、含まれる機能、含まれない機能、必要な出生情報、期限に関する注意を表示する。
- CTAは同じ商品・言語・販売元の引換フォームへ進む。
- ACGは正確な出生時刻が必要であることを入力前に示す。
- FULL版には1年Plannerを含むこと、ACGとMuseumを含まないことを示す。
- ACG bundleにはACGと1年Plannerを含み、Museumを含まないことを示す。
- 休止中のPlanner単体を販売中の選択肢として積極表示しない。

### 3.2 注文・出生情報入力

- 注文情報欄は画面言語に応じて「オーダー番号」「Order ID」等の一般名称を使い、特定販売元限定に見せない。
- 販売元がURL等で確定している場合は内部状態として引き継ぐ。購入者に不要な選択を増やさない。
- 国内出生地は表示用の都道府県ラベルと、座標解決に使う日本語内部値を分離する。
- 海外出生地は都市、緯度・経度、タイムゾーン等の必要情報を入力または検索できる。
- 出生時刻は「正確」「おおよそ」「不明」を区別する。おおよそ・不明では時刻依存項目が暫定であることを確認画面で示す。
- 最終確認前に、生年月日、時刻精度、出生地、商品種別を購入者が確認できる。
- 送信時は二重送信を防ぐ。

### 3.3 成功・再訪

- 新規発行は1つの発行権を原子的に消費し、`/chart/{token}` へ進む。
- 言語を結果URLへ引き継ぐ。
- 同じ注文に残枠がある場合は「使用済み注文」として全面拒否せず、次の1枠を発行できる。
- 同じ注文に複数の生成済み結果がある場合は、購入者が既存結果を区別して再表示できる状態にする。
- 数量を超えた場合は枯渇として案内し、既存結果を失わせない。
- 注文番号だけで販売元を混同しない。基幹識別は販売元を含む。

### 3.4 Personal Editionコード

- コード方式は通常注文番号方式と分けて表示する。
- 有効なコードで1回だけPersonal Editionを生成し、失敗時は安全にコード予約を解放する。
- ACGコードは正確な出生時刻を必須とする。
- 現行成果物はSTART方式とし、旧アクティベーション資料を通常配布しない。

## 4. エラー仕様

| 状態 | 購入者への案内 |
|---|---|
| 必須入力不足・形式不正 | 該当項目を修正できる同じ画面。安全な入力値は保持 |
| 注文が見つからない | 入力確認を促し、必要に応じて同期後に再照合。内部同期結果は露出しない |
| 商品が違う | 購入商品と選択商品が一致しないことを明示。別商品を勝手に発行しない |
| 使用可能数が0 | 追加発行不可と、既存結果を確認する導線を分ける |
| 出生時刻がACG要件を満たさない | 正確な時刻が必要であることを表示。仮時刻でACGを発行しない |
| 計算・保存失敗 | 再試行可否を案内。内部例外やDB情報を表示しない |

## 5. 言語・後方互換

- JA / EN / ES / DEで見出し、ラベル、placeholder、確認文、エラー、遷移先を統一する。
- `lang` 未指定の既存URLは日本語を維持する。
- 既存の日本語都道府県内部値、既存注文、既存チャートURLを変更しない。
- 古い注文に明細発行権がない場合のfallbackはサーバー側で限定的に行い、現行商品の不正な流用を許さない。

## 6. 受入テスト

### 自動テスト

- 各商品slugの開始画面から正しい引換URLへ進む。
- JA / EN / ES / DEの表示文、フォームラベル、エラー、結果URLが同じ言語になる。
- 国内／海外、正確／おおよそ／不明の各出生時刻精度で表示と検証が変わる。
- Etsy / STORES / Payhipの注文を販売元込みで識別する。
- 数量1、数量2、同一注文の複数SKU、残枠、枯渇、同時送信を検証する。
- 商品不一致では発行権もチャートも作られない。
- 保存失敗時に発行権だけが消費されない。
- Personal Edition生成失敗時にコード予約が解放される。

主なテスト: `tests/test_order_intake_and_redeem.py`, `tests/test_multi_purchase_entitlements.py`, `tests/test_order_code_input_forms.py`, `tests/test_redeem_overseas_map.py`, `tests/test_personal_edition_activation.py`。

### 手動テスト

- スマートフォン幅で入力、エラー修正、確認モーダル、送信が完結する。
- ブラウザの戻る操作で二重発行しない。
- 実メール同期を伴う試験は専用テスト注文だけを使い、登録前後の発行権数を確認する。
- 本番試験では顧客注文を使用しない。
