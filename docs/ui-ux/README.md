# 購入体験 UI/UX 機能仕様書 — 索引

最終更新: 2026-08-29

## 1. 目的

このディレクトリは、購入者と運用者が実際に触る画面について、実装・レビュー・回帰テストの共通基準を定める。占星術計算の正しさではなく、次を確認対象とする。

- 誰に、どの画面・操作を表示するか
- 入力、遷移、再訪、エラー時に何が起きるか
- JA / EN / ES / DE の言語がどこまで引き継がれるか
- 商品構成、販売元、数量、期限を誤解させないか
- 個人情報、注文情報、保存済みYAMLを安全に扱うか
- 自動テストと人による画面確認で何を合格条件とするか

実装の正本は `routes.py`、`templates/`、`services/`、`tests/` である。本仕様書とコードが食い違う場合は、差異を不具合または仕様変更候補として記録し、黙って文書だけを合わせない。

## 3. 共通UI/UX原則

### 3.1 言語

- 購入体験の対応言語は `ja` / `en` / `es` / `de` とする。
- 全サイトの既定言語を一括変更しない。通常画面は `lang` 未指定時に既存互換の日本語を維持する。
- `/demo/neko` の入口だけは既存販売サンプル互換のため未指定時英語とする。配下の直リンクは共通解決規則に従うため、販売導線では必ず `lang` を明示する。
- ページ内リンク、フォームPOST後、生成結果、PDF、AI依頼文まで同じ言語を引き継ぐ。
- 内部値は翻訳しない。日本語都道府県名、商品種別、SKU、計算キー等は保存・照合用の正規値として維持し、表示ラベルだけを翻訳する。
- 翻訳欠落時に他言語を混在させず、定義済みfallbackを使う。購入者向け文言の欠落を辞書キーのまま表示しない。

### 3.2 商品構成

- FULL版は1年Plannerを含む。ACGとBirth Chart Museumは含まない。
- ACG bundleはACGと1年Plannerを含む。Birth Chart Museumは含まない。
- Planner単体は別SKUだが休止中。新規販売導線や、販売中と誤認するCTAを出さない。
- Add-onはベースとなるFULL版等のYAMLまたはURLを利用するが、別売Add-onの購入証明が必要である。note特典は例外ルートとして分離する。
- Museumは全有料商品から除外し、無料アプリとして既存URLを維持する。

### 3.3 操作とエラー

- 主操作は1画面に1つの明確なCTAを置き、補助操作は視覚的優先度を下げる。
- 送信中・生成中は二重送信を防ぎ、処理中であることを表示する。
- 入力エラーでは、秘密値を除き安全な入力内容を保持し、該当項目を修正できる状態で同じ画面へ戻す。
- エラーは購入者の選択言語で表示し、内部例外、SQL、秘密情報、API応答本文を直接露出しない。
- 期限切れ、使用済み、数量枯渇、商品違いは別の状態として案内する。

### 3.4 セキュリティとプライバシー

- 個人情報入力、注文照合、コード発行、管理画面は `no-store` を基本とする。
- URLへ出生情報や注文番号を埋め込まない。公開可能なランダムトークンまたは期限付きURLだけを使う。
- 保存済みYAMLを別機能へ渡す場合は、同一オリジンの限定URLを使い、外部サイトへRefererで漏らさない。
- 管理認証、DB初期化、メール同期、リセットは表示層でなくサーバー側で拒否できなければならない。

### 3.5 アクセシビリティと端末

- CTAとフォームはキーボード操作でき、状態は色だけで表現しない。
- ボタン・言語切替には見えるラベルまたは適切な `aria-*` を付ける。
- 主要フローはスマートフォン幅で横スクロールせず操作できることを目視確認する。
- 新しいタブを開くリンクは、現在の入力や結果を失わない用途に限定する。

## 4. 共通リリースゲート

1. 仕様変更と対応する受入条件を、該当する機能別仕様書へ追記する。
2. 自動テストで正常系、入力エラー、期限・使用済み、言語、後方互換を確認する。
3. Push済みのクリーンなコミットから0%候補版を作る。
4. 候補URLでJA / EN / ES / DE、スマートフォン幅、主要CTA、戻る・再訪を確認する。
5. 注文・DBを使う試験は、専用テスト注文と期待する発行権数を事前に決める。
6. 本番切替は候補確認後の明示承認を必要とする。
7. 本番切替後にヘルス、主要画面、直前の不具合修正点を再確認する。
8. 旧リビジョンを即時削除せず、ロールバック先として保持する。

## 5. テスト記録の書き方

各テスト結果は、少なくとも次を残す。

- 対象コミットと候補／本番リビジョン
- URL、言語、商品種別、販売元。ただし実注文番号や顧客情報は仕様書へ記載しない
- 期待結果と実結果
- 自動テスト件数と対象ディレクトリ
- 手動確認した端末幅、ブラウザ、PDF・ZIP・動画等の成果物
- 既知の許容例外と、未確認の項目
