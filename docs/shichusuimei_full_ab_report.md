## 2. 測定条件と架空ケース

- tiktoken **0.14.0**、**o200k_base**。既存のローカル定義キャッシュを読み、ネット取得は無効化。実モデルのAPI課金トークンやClaudeトークンの測定ではない。
- YAML：UTF-8、BOMなし、LF。文字数はPython文字列長。完全版の正式値は保存済み原本のバイト列。推奨／通常はPyYAMLでUnicode・元のキー順・width=120、短い辞書／リストをflow形式で出力。
- セクションは `yaml.safe_dump(allow_unicode=True, sort_keys=False, width=120)` で同条件の部分文書を生成。アンカー・インデント・分割境界の違いで**非加算の寄与目安**となる。全体の原本／派生ファイルの実測が正式値。
- 必要なAI利用指示付き値は、版別のローカル指示＋区切り＋YAMLを実際に連結して計測。既存送信プロンプトは変更していない。チャット包絡・回答用の余裕は含めない。
- 春／冬／夏は既存 `tmp/annual_prototype/*_base.yaml` の架空保存Fullをそのまま利用。既報3.4〜3.8万の数字を転記せず、ファイルを再度トークナイズした。
- 境界3例はfixture作成時だけ既存エンジンを使い、固定as_ofの原本を保存してから派生する。派生処理はエンジンを呼ばない。立春前後は出生日時変更ではなく、同じ命式の適用流年の切替を検証する。
- 旧形式例は現在の架空データから新規構造分析／予測等を外した**旧形式を模したfixture**。実際の旧購入者データを取得したものではない。旧形式全バリエーションの互換性は未検証。
- 別途、4柱に同じ甲子、大運1／7と流年2026／2086に同じ丙午・同じ関係を置いた同一値の対象検証fixtureも用意。実際に計算した出生図ではなく、参照・対象位置だけの検証用。

## 4. 3版の仕様と実測

**完全版**：元のファイルをバイトコピーしSHA-256一致を確認。新エンジンで再計算した結果との比較ではない。

**推奨版（名称は試作用）**：全項目を残す。短い辞書／リストの記法、同一対象内の厳密な型・値一致、共通の長文を名前付きYAMLアンカーで整理。一定の繰り返し一覧は、読み取れる列名付き `columns`／`rows` 表現に変換。略語への置換・数値丸め・行の削除・関係の間引きはしない。デバッグ／環境情報も全保持し、開発情報だから意味がないとは判断していない。アンカー・列の説明は必要指示のトークンに含めた。

**通常版（収録範囲の候補）**：以下を保持し、既存10年予測だけを期間・項目名付きで省略。商品からの撤去・別売への移動は実装していない。

| 用途 | 保持する計算根拠 |
|---|---|
| 性質／強み・弱み | 出生四柱、日主、蔵干・十神・十二運・五行、身強弱スコアと内訳、通根・透干、構造分析・格局／用神候補と方式・根拠・競合条件 |
| 仕事・金運 | 十神の強度／配置、各十神の関係・流れ、原局内の干合・刑冲合害等、構造分析の限界・未判定・条件。吉凶や鑑定品質を自動採点しない |
| 大運の基本的な流れ | 全10期の起運方式、年齢・概算日時、各期の構造・原局との作用、境界の注意事項 |

## 6. 既存流年試作を変更しない合計測定

通常版も大運・原局構造をすべて残すため、この3ケースの追加試作に必要な共通情報は不足しない。推奨版は**ローカル復元後の基本辞書**で照合した結果である。既存ローダーへ表形式を無変更で渡せるという意味ではない。AI用の参照は各ファイル内で解決し、基本と追加を両方渡す前提。旧形式fixture・境界fixtureには対応する既存追加サンプルがないため、組合せの正式測定は行わない。
